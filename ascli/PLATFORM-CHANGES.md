# Platform changed? Update ascli.

ascli's commands are **generated** from the platform's own `/api/capabilities/docs`, not written by
hand. When you add, rename or remove an action on the platform, regenerate:

```sh
make -C ascli generate     # reads the docs fixture, rewrites internal/cmds/commands_gen.go
make -C ascli check        # the full gate: vet, drift check, tests
```

`make -C ascli check` is what CI runs, and it **fails the build** if the platform has moved and
nobody regenerated. You will not ship an out-of-date client by forgetting; only by skipping the
check.

If the phone is connected, generate straight from it instead of the fixture:

```sh
make -C ascli generate-go-live   # or: go run ./cmd/generate --live
```

## What the check tells you

```
+ download-manager pull     the platform has this, the CLI does not
- download-manager grab     the CLI has this, the platform does not
~ camera capture            the platform now takes parameters this command does not
      + --flash
```

## Why the fixture and not the phone

`testdata/docs.json` is a copy of the docs payload, regenerated by the platform's own
`DocsFixtureTest` and committed. Generating from it means the build does not need a phone attached,
and `ascli capabilities` still works on a machine that has never connected to anything.

The fixture and `tools/fixtures/docs-sample.json` — the one the HTML console is checked against —
are the same payload, deliberately. One source, so the console and the CLI cannot each be right
about a different API.
